# Domain documentation

This repository uses one context: root `CONTEXT.md` and `docs/adr/`.
Before terminology or design work, read `CONTEXT.md` and the ADRs relevant to the
area being changed. If they do not exist, proceed without scaffolding them.

Use the vocabulary defined there. Identify any conflict with an existing ADR
explicitly instead of silently overriding its decision. Domain documents are
created lazily when terminology or decisions are resolved.
